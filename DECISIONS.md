# DECISIONS.md

Decisions not covered by CLAUDE.md, boring option preferred.

- **2026-07-23 — Flank marinade slugs vs versions.** §11 lists `flank-quick` and `flank-overnight` as two slugs, while §11 prose says versioned marinades become two `recipe_version` rows on one recipe. Slug list wins (QR contract): imported as two recipes, each with one v1 version. The version mechanism stays available for future edits of either.
- **2026-07-23 — pgvector extension enabled in the initial migration** even though `chunk`/`book` tables arrive in Phase 3 — enabling an extension is idempotent and avoids a superuser step mid-project. No Phase 3 tables scaffolded.
- **2026-07-23 — Ollama not in compose.** Host already runs it; referenced via `OLLAMA_URL` env (`host.docker.internal:11434` default).
- **2026-07-23 — Reference Docs/ kept in repo** as historical source material (v1 single-file prototype, master file original, print PDF, logo source). The zip is gitignored.
- **2026-07-23 — Phase 3 RAG delegated to the Atlas stack** (user direction). No in-app chunker/embedder/watcher, no book/chunk tables. Corpus = `\\Olympus_NAS\Media\References\Cooking`, auto-ingested by Atlas `rag-ingest.timer` into Qdrant `references_v2`; retrieval via rag-api :8099 with client-side folder filter (rag-api takes only {question, top_k}); synthesis via LiteLLM `cluster` alias (GB10s). Cooking shelf treated as private tier → local models only; AnthropicProvider hard-refuses corpus chunks. Possible later improvement on Atlas: server-side source_folder filter on /retrieve.
- **2026-07-23 — Categories follow recipes-master.md headers** (e.g. "Sauces, Dressings & Salsas"); empty categories (Appetizers, Baking, Desserts, Preserves) are not imported as recipes and simply don't appear until they have one.
- **2026-07-26 — `shopping_item.amount` is numeric, not the `text` sketched in CLAUDE.md §5.** The whole point of the list is that adding a second recipe *adds* to a line rather than replacing it, and "3 tbsp" + "2 tbsp" = "5 tbsp" needs arithmetic. Amount is a float with a separate `unit`; the display string is derived on read via `services/scaling.format_amount`, so quantities read identically to everywhere else in the app (kitchen fractions, em dash for to-taste). Also added `to_taste` and `recipes` (contributing slugs) columns; dropped `plan_week` since the meal-plan grid is not built and a single running list is what was asked for.
- **2026-07-26 — Shopping list merges by ingredient name before the first comma.** Recipe names carry preparation ("beef chuck, cut into 1-inch cubes"); you buy beef chuck. Units convert within a family (tsp/tbsp/cup/ml, and g/oz/lb) and never across one — 2 cups of stock and 400 g of beef are not the same line. The display unit is the one contributing the largest share, so the list keeps the cook's own idiom. Plural stripping uses an explicit exception list (`asparagus`, `molasses`, …) because no suffix rule separates those from `limes`.
- **2026-07-26 — Library search filters index/contents pages before ranking** (`services/passages.py`). A cookbook index contains "French Onion Soup" verbatim and so outranks the actual recipe; 8 of 22 chunks retrieved for that query were index pages. Classified by sentence count, short-line fraction and digit density — digits separate an ingredient list (which must survive) from an index (which must not). Adjacent chunks from one document are merged into continuous passages. Read-side only; ingestion is untouched.
- **2026-07-26 — Atlas: the api container joins the external `ai-stack_ai` network** and addresses `rag-api:8099` / `llm-router:4000` by container name. Reaching them on the host's Tailscale IP times out from inside a container (the docker bridge has no route back to `tailscale0`), and `host.docker.internal` fails the same way. Symptom when wrong: `rag_health.ok: false`, empty Library, `/ask` hanging until timeout.
- **2026-07-27 — Cross-language parity is enforced by generated fixtures, not by comment.** `shared/fixtures/*.json` holds hand-curated inputs with expectations **generated from the live Python** (`api/scripts/dump_fixtures.py`); pytest and XCTest both read them, and CI fails on stale fixtures. Hand-typed expectations only pin what someone remembered to type. Prompted by finding `SampleDataSource.glutenWatch` at 14 terms against `shopping.py`'s 23 (missing `curry powder, spice blend, seasoning, gravy, sausage, bacon, imitation crab, surimi, oats`) and `AISLE_ORDER` hand-copied in four places. Verified by breaking the §8 round-to-5 rule in Python, regenerating, and watching the Swift suite go red on `metric-above-the-boundary-rounds-to-5`. Swift fixtures resolve via `#filePath`, so those tests are simulator-only — accepted, since everything covered is a pure function and bundling copies would recreate the stale-duplicate problem.
- **2026-07-27 — The iOS project gained its first unit-test target.** There was none; Swift logic had never been tested. Hand-written into `project.pbxproj` in the existing style and verified with `xcodebuild test` from the CLI before opening Xcode (which rewrites the file). The project uses `PBXFileSystemSynchronizedRootGroup`, so this is the last pbxproj edit needed — new source files are compiled automatically.
- **2026-07-27 — `Lexicon.half_suffixes` is a dict of phrase→value, and the fraction may follow the unit.** Writing parity fixtures for the Swift port exposed two silent bugs in `services/ingredients.py`. (1) Every half-suffix added 0.5, so "2 and a quarter cups flour" parsed as 2.5; the word form ("two and a quarter") went through the `_ones` table and was correct, which is why it hid. (2) Only the quantity-fraction-unit word order was handled, so "a cup and a half of cream", "o cană și jumătate de lapte" and "une tasse et demie de lait" stranded the fraction in the ingredient *name* with the amount short by up to 0.75 — English, French and Romanian all permit both orders. The `halves` regex now takes an optional canonical unit between the number and the suffix. Printed-text behaviour is unchanged; the seed importer still round-trips.
- **2026-07-27 — Ordered arrays, not dictionaries, for anything feeding a regex alternation.** Python dicts iterate in insertion order and `sorted` is stable, so `_alternation` is deterministic there. Swift `Dictionary` order is unspecified, which would make the parser's behaviour depend on hash seeding. `IngredientParse.Lexicon` therefore stores `units`/`numbers`/`categories` as `[(String, String)]` and builds lookup dictionaries separately. Same reasoning as the `(-count, index)` sort key in `Aisles`.
- **2026-07-27 — `Support/OfflineParse.swift` deleted.** It was a deliberate approximation ("does not try to be the full lexicon") for the simulator. `Domain/IngredientParse.swift` is the full fixture-pinned port, and `SampleDataSource` now uses it, so the DEBUG path rehearses the local notebook instead of approximating it.
- **2026-07-27 — The local notebook is one JSON file per recipe under `Application Support/Notebook/`, included in backup.** `JSONStore` takes `excludedFromBackup` as a *required* parameter rather than a default, because the two users of it need opposite answers: `RecipeCache` excludes itself (everything in it is re-fetchable from the server), while `LocalStore` must not (it is the only copy of a guest's recipes, and a lost iPad would take them). One file per recipe means small atomic writes and a corrupt file loses one recipe rather than the notebook; the list is derived by scanning the directory, so there is no index and therefore no index-consistency bug class. No SQLite, no SwiftData — 20 recipes at ~51 KB do not need a database.
- **2026-07-27 — Ask and the Library are absent in local mode, not disabled.** They read the owner's private, copyrighted corpus, which CLAUDE.md §1 keeps inside the local deployment; a device-hosted notebook has no route to it. `LocalDataSource` throws `APIError.localOnly` rather than returning empty results, because empty reads as "there is no onion soup recipe" when the truth is "this device was never going to have one". `qrURL` returns nil for the same reason — a printed QR resolving to nothing is worse than no QR.
