- **2026-07-23 — Categories follow recipes-master.md headers** (e.g. "Sauces, Dressings & Salsas"); empty categories (Appetizers, Baking, Desserts, Preserves) are not imported as recipes and simply don't appear until they have one.
- **2026-07-26 — `shopping_item.amount` is numeric, not the `text` sketched in CLAUDE.md §5.** The whole point of the list is that adding a second recipe *adds* to a line rather than replacing it, and "3 tbsp" + "2 tbsp" = "5 tbsp" needs arithmetic. Amount is a float with a separate `unit`; the display string is derived on read via `services/scaling.format_amount`, so quantities read identically to everywhere else in the app (kitchen fractions, em dash for to-taste). Also added `to_taste` and `recipes` (contributing slugs) columns; dropped `plan_week` since the meal-plan grid is not built and a single running list is what was asked for.
- **2026-07-26 — Shopping list merges by ingredient name before the first comma.** Recipe names carry preparation ("beef chuck, cut into 1-inch cubes"); you buy beef chuck. Units convert within a family (tsp/tbsp/cup/ml, and g/oz/lb) and never across one — 2 cups of stock and 400 g of beef are not the same line. The display unit is the one contributing the largest share, so the list keeps the cook's own idiom. Plural stripping uses an explicit exception list (`asparagus`, `molasses`, …) because no suffix rule separates those from `limes`.
- **2026-07-26 — Library search filters index/contents pages before ranking** (`services/passages.py`). A cookbook index contains "French Onion Soup" verbatim and so outranks the actual recipe; 8 of 22 chunks retrieved for that query were index pages. Classified by sentence count, short-line fraction and digit density — digits separate an ingredient list (which must survive) from an index (which must not). Adjacent chunks from one document are merged into continuous passages. Read-side only; ingestion is untouched.
- **2026-07-26 — Atlas: the api container joins the external `ai-stack_ai` network** and addresses `rag-api:8099` / `llm-router:4000` by container name. Reaching them on the host's Tailscale IP times out from inside a container (the docker bridge has no route back to `tailscale0`), and `host.docker.internal` fails the same way. Symptom when wrong: `rag_health.ok: false`, empty Library, `/ask` hanging until timeout.
- **2026-07-27 — Cross-language parity is enforced by generated fixtures, not by comment.** `shared/fixtures/*.json` holds hand-curated inputs with expectations **generated from the live Python** (`api/scripts/dump_fixtures.py`); pytest and XCTest both read them, and CI fails on stale fixtures. Hand-typed expectations only pin what someone remembered to type. Prompted by finding `SampleDataSource.glutenWatch` at 14 terms against `shopping.py`'s 23 (missing `curry powder, spice blend, seasoning, gravy, sausage, bacon, imitation crab, surimi, oats`) and `AISLE_ORDER` hand-copied in four places. Verified by breaking the §8 round-to-5 rule in Python, regenerating, and watching the Swift suite go red on `metric-above-the-boundary-rounds-to-5`. Swift fixtures resolve via `#filePath`, so those tests are simulator-only — accepted, since everything covered is a pure function and bundling copies would recreate the stale-duplicate problem.
- **2026-07-27 — The iOS project gained its first unit-test target.** There was none; Swift logic had never been tested. Hand-written into `project.pbxproj` in the existing style and verified with `xcodebuild test` from the CLI before opening Xcode (which rewrites the file). The project uses `PBXFileSystemSynchronizedRootGroup`, so this is the last pbxproj edit needed — new source files are compiled automatically.
- **2026-07-27 — `Lexicon.half_suffixes` is a dict of phrase→value, and the fraction may follow the unit.** Writing parity fixtures for the Swift port exposed two silent bugs in `services/ingredients.py`. (1) Every half-suffix added 0.5, so "2 and a quarter cups flour" parsed as 2.5; the word form ("two and a quarter") went through the `_ones` table and was correct, which is why it hid. (2) Only the quantity-fraction-unit word order was handled, so "a cup and a half of cream", "o cană și jumătate de lapte" and "une tasse et demie de lait" stranded the fraction in the ingredient *name* with the amount short by up to 0.75 — English, French and Romanian all permit both orders. The `halves` regex now takes an optional canonical unit between the number and the suffix. Printed-text behaviour is unchanged; the seed importer still round-trips.
- **2026-07-27 — Ordered arrays, not dictionaries, for anything feeding a regex alternation.** Python dicts iterate in insertion order and `sorted` is stable, so `_alternation` is deterministic there. Swift `Dictionary` order is unspecified, which would make the parser's behaviour depend on hash seeding. `IngredientParse.Lexicon` therefore stores `units`/`numbers`/`categories` as `[(String, String)]` and builds lookup dictionaries separately. Same reasoning as the `(-count, index)` sort key in `Aisles`.
- **2026-07-27 — `Support/OfflineParse.swift` deleted.** It was a deliberate approximation ("does not try to be the full lexicon") for the simulator. `Domain/IngredientParse.swift` is the full fixture-pinned port, and `SampleDataSource` now uses it, so the DEBUG path rehearses the local notebook instead of approximating it.
- **2026-07-27 — The local notebook is one JSON file per recipe under `Application Support/Notebook/`, included in backup.** `JSONStore` takes `excludedFromBackup` as a *required* parameter rather than a default, because the two users of it need opposite answers: `RecipeCache` excludes itself (everything in it is re-fetchable from the server), while `LocalStore` must not (it is the only copy of a guest's recipes, and a lost iPad would take them). One file per recipe means small atomic writes and a corrupt file loses one recipe rather than the notebook; the list is derived by scanning the directory, so there is no index and therefore no index-consistency bug class. No SQLite, no SwiftData — 20 recipes at ~51 KB do not need a database.
- **2026-07-27 — Ask and the Library are absent in local mode, not disabled.** They read the owner's private, copyrighted corpus, which CLAUDE.md §1 keeps inside the local deployment; a device-hosted notebook has no route to it. `LocalDataSource` throws `APIError.localOnly` rather than returning empty results, because empty reads as "there is no onion soup recipe" when the truth is "this device was never going to have one". `qrURL` returns nil for the same reason — a printed QR resolving to nothing is worse than no QR.
- **2026-07-27 — Exactly one notebook mode per device; nothing syncs, ever.** `AppMode` is `.server` or `.local`, chosen at first run and switchable in Settings, but switching never copies or merges data. Two writable copies with no shared clock is a merge problem, and the honest UI for "your iPad and the server disagree about the goulash" is a conflict resolver nobody wants in a kitchen. The Settings alert states plainly that nothing is copied in either direction.
- **2026-07-27 — Mode migration runs once, is persisted, and is biased entirely towards `.server`.** An existing install must never silently open an empty local notebook — that reads as the app having eaten the user's recipes. Four signals mean "existing": a stored `sharpedge.baseURL`, an existing `RecipeCache/recipes.json`, a Keychain token, or a written `sharpedge.gfOnly`. The last two work because `baseURLString`/`gfOnly` are assigned inside `AppConfig.init`, where Swift does not fire `didSet`, so on a genuinely fresh install neither key exists. Which signal fired is recorded in `sharpedge.modeOrigin` for diagnosis. Fresh installs default to `.local` because the built-in default URL is the owner's private Tailscale address. **Observed:** Keychain items survive app deletion on the simulator, so a reinstall can report `keychainToken` and skip the chooser; the bias is in the safe direction and a reinstall by the same person skipping it is acceptable.
- **2026-07-27 — `AppEnvironment` rebuilds its data source explicitly, not through Combine.** The old pipeline merged three `@Published` publishers, dropped three *combined* events via a literal `.dropFirst(3)` (which breaks silently when a fourth published property is added), and debounced 150 ms. The debounce was a real bug: `SettingsView.commit()` mutated the config and the next line read `env.dataSource`, so "Test connection" tested the previous server with the previous token. A `generation` counter replaces the literal and every `.task(id:)` keys off it, so a mode switch reloads every screen rather than leaving stale recipes that look like data loss.
- **2026-07-27 — Settings and setup validate against a throwaway client, never `env.dataSource`.** `ServerProbe` builds its own `APIClient` from the typed URL and token, checks reachability, decodes `/recipes` to confirm the host is actually a Sharp Edge server (nothing checked this before — any HTTP host passed, then failed with a decoding error deep inside a screen), and probes the token with an authenticated no-op. Settings only persists values the probe accepted. This replaces a "Test connection" that read the live data source immediately after `commit()` and therefore tested the previous server with the previous token.
- **2026-07-27 — Export format `sharp-edge-notebook` v1, extension `.sharpedge`.** One envelope for a single recipe or a whole notebook, so the importer has no branch; inner recipes reuse `VersionOut` so the `versions` array is byte-compatible with the API wire format. Decoding is strict — an unknown `format`, a `version` newer than this build, or an empty file is refused rather than partly read, because best-effort decoding silently drops what it does not understand into a permanent record. Single-recipe export works in both modes (the owner is the one with recipes to send) and carries only the current version; whole-notebook export is local-mode only, since from a server it is 20×(1+versions) requests and a partial failure has no good answer.
- **2026-07-27 — Imports are always confirmed, and collisions default to rename.** All three arrival routes (Files picker, `onOpenURL`, AirDrop) funnel into one preview sheet; an "open with" that mutates the notebook on tap is how people lose recipes. A colliding slug defaults to `-2` rather than overwrite because slugs are a QR contract (CLAUDE.md §5) and an incoming recipe is a different dish that happens to share a name; "add as a new version" is offered because append-only makes it lossless, and identical content defaults to skip. Imported histories are renumbered from 1 with exactly one current version.
- **2026-07-27 — A lexical channel re-ranks the retrieved pool; it does not query a local index.** CLAUDE.md §3 specifies Postgres FTS + pgvector with RRF, which assumed chunks live in Postgres. §9 moved the corpus to Atlas's Qdrant and made this app a consumer, so `services/lexical.py` runs BM25 over the **over-fetched candidate pool** (IDF therefore means "rare among what was retrieved") plus a phrase bonus and heading weighting, fused with the vector ranking by RRF at k=60. Fusion rather than score-blending because the channels are not on comparable scales — the observed vector scores for one query spanned 0.013–0.032, and normalising a range that narrow amplifies noise into apparent signal. **Honest limit:** this reorders what Atlas returned and cannot surface a passage that was never retrieved, so `rag_fetch_k` bounds the achievable quality. Ranking runs *after* passage merging so several fragments of one recipe cannot occupy several result slots.
- **2026-07-27 — A table of contents is detected by where its digits sit, not how many.** The existing digit guard treats digits as evidence of quantities and so waved contents pages through as ingredient lists. A contents line *ends* with a page number ("Onion Soup 335"); an ingredient line *starts* with a quantity ("40 grams Vidalia onion"). Measured on the corpus: 0.78 lines-ending-in-digits for the CIA contents page versus 0.00 for every genuine ingredient list retrieved beside it. The check runs before the segment-count guard, because a dense contents column has almost no blank lines (~2 blank-line segments) and would otherwise exit early.
- **2026-07-27 — Atlas rag-api gained a read-only `POST /chunks`, and this app expands its top hits through it.** A retrieval hit is one ~3200-char window, so a recipe arrived as a fragment. The new endpoint returns a contiguous window by `(doc_id, chunk_index)` using the deterministic point ids `qdrant_ops.make_point_id` already computes — purely additive, no existing endpoint touched, so the other consumers of that shared stack (family-hub, intel-amplifier, bookmarks) are unaffected. Source files backed up on Atlas as `main.py.bak-neighbours` and `qdrant_ops.py.bak-neighbours`. `services/expand.py` pulls the window for the top 4 results only (one request each) and strips the 480-char chunk overlap, or a recipe reads with every few lines repeated. It degrades silently: an older rag-api 404s and search continues on unexpanded passages. **Result:** average passage 800 → 3468 chars, page coverage 33/43 → 39/45, and CLAUDE.md's Phase 3 gate ("how does Escoffier build an espagnole?" answers with page-cited chunks) now passes with p.291/p.294/p.13.
- **2026-07-27 — Page numbers are inferred from `[page N]` markers in *neighbouring* chunks.** The marker denotes where a page *begins*, so the nearest marker at or before the hit is the page it sits on; if every marker is after it, the hit is on the page before. No marker anywhere still yields no page — a wrong number sends someone to the wrong page of a 1,200-page textbook, which is worse than none.
- **2026-07-27 — Correction to an earlier diagnosis recorded here.** The retrieval scores of 0.013–0.032 were described as "noise" suggesting a bad embedding. They are **RRF fusion scores from Qdrant's hybrid search** — `1/(60+rank)` is exactly that range — and a cross-encoder reranker already runs on top, producing a properly discriminating 3.5–5.8 in `rerank_score`. `HYBRID_ENABLED`, `RERANK_ENABLED` and `MULTI_QUERY_ENABLED` were all already true on Atlas. The embedding was never the problem; the fragment size and missing pages were.

- **2026-08-25 — Photo import: vision transcribes, our parser structures.** Three approaches were tried against real pages. Asking a small vision model (minicpm-v) for JSON was fast but wrong ("250 g de farine" → unit "de farine", no amount). Asking a large one (gemma3:27b) for JSON was right but slow (48 s) — long enough that a phone screen locked mid-read and iOS killed the socket. Adding a text model to tidy the transcript corrupted it (rewrote "50 cl" as "50 ml", invented an ingredient). What works: **one** vision call that only transcribes into a LANG/TITLE/YIELD/INGREDIENTS/STEPS/NOTES layout (~11 s on gemma3, byte-identical across runs), then `services/ingredients.py` — the parser dictation already uses — turns the lines into quantities. No model ever paraphrases the cook's words, and structure comes from tested code. Router aliases: `vision` = gemma3:27b on Wile, `vision-fast` = minicpm-v on RoadRunner, both `keep_alive: 60m`.
- **2026-08-25 — cl/dl and written unit abbreviations added to the shared parser.** European pages say "50 cl", "2 EL", "2 c. à s." constantly; the parser kept the amount but dropped the unit. Written text now expands them (dictation untouched — its lexicon handles the spoken forms and their articles better). Ported to the Swift twin, parity fixtures regenerated.
- **2026-08-26 — Reading a recipe in another language is a lens, not an edit.** A photographed page keeps the cook's own words (CLAUDE.md §1), which is right for the notebook and useless when the cook can't read Romanian. `recipe_translation` (migration 0007) caches one translation per *version* per language: keyed on the version so an edit can never show stale translated words against new content, and cached so the big model runs once rather than on every view. Reads need no token (the point is opening a recipe on a phone); creating one is a write like any other. The stored recipe is never modified — the toggle only changes what the screen shows, and quantities always come from the recipe itself, never from the translation. Model: `translate` alias → qwen3.5:122b on Wile; qwen2.5:14b and 72b both failed real Romanian food words (72b rendered *gălbenușuri* as "marigolds"), while 122b got every term right.
